s3dol.uploads¶

Direct-to-S3 browser uploads: a presigned POST scoped to a key prefix.

A browser can upload straight to S3 without the server relaying bytes: the server issues a presigned POST form whose signed policy pins

  • the exact key (server-generated <prefix><random token>: the client never picks a filename, so it can neither overwrite a sibling object nor smuggle .. segments; a form holds one object, and on an unversioned bucket re-posting with it only overwrites that object, so the byte budget cannot be multiplied; see “Versioned buckets” below),

  • a content-length range (min_bytes..``max_bytes``),

  • the content type (optional), and

  • an expiry (the 7-day SigV4 cap; an STS session’s own expiry still ends it sooner).

Before signing, an optional budget callable is asked to reserve the bytes (budget(max_bytes) raises UploadBudgetExceeded to refuse, and may return a release() callable that is called if signing fails), so a daily per-tenant byte budget is enforced before any form exists. DailyByteBudget is the ready-made one; any callable works.

Versioned buckets. The budget caps what one form can store only when the bucket keeps one version per key. With versioning Enabled, every re-post of the same form within its expiry stores a new full version, so one reservation of max_bytes can buy N * max_bytes of storage. Use an unversioned bucket for uploads, or one with a lifecycle rule that expires noncurrent versions promptly. When a budget is given, presigned_upload() asks the bucket for its versioning status and, per on_versioned_bucket, warns (the default, VersionedBucketWarning), refuses (ConfigurationError) or skips the check ('ignore', no extra call).

The function is host-agnostic: it takes the store, the prefix and the limits as arguments, and the web app mounts it behind its own auth:

form = s3dol.presigned_upload(
    store, key_prefix='tenant-7/', max_bytes=5_000_000, content_type='image/png')
form.url, form.fields      # hand both to the browser's <form>/FormData

>>> from s3dol.uploads import DailyByteBudget
>>> budget = DailyByteBudget(100, today=lambda: '2026-01-01')
>>> _ = budget(60); _ = budget(40)
>>> budget(1)

class s3dol.uploads.DailyByteBudget(limit_bytes, *, ledger=None, today=<function DailyByteBudget.<lambda>>)[source]¶

Bases: object

A per-day byte budget (one instance per tenant); call it to reserve.

ledger is any MutableMapping[str, int] (default: in-memory) keyed by day, so persistence is a one-argument swap (a dol store, a file…). today is the clock seam. Reservation is optimistic (the maximum the form allows), and a form holds exactly one key, so re-posting cannot multiply the budget on an unversioned bucket (on a versioned one each re-post stores a new version: see the module docstring).

s3dol.uploads.presigned_upload(store, *, key_prefix, max_bytes, content_type, min_bytes=0, expires_in=900, budget=None, on_versioned_bucket='warn')[source]¶

A presigned POST form for ONE new object under key_prefix.

content_type is required: pass the one type to accept, or None to explicitly accept any (then a holder can store text/html: do not serve such objects from a trusted origin).

key_prefix must end with the store’s delimiter (tenant-7/ cannot match tenant-77/) and is in the store’s key space (the store’s own prefix is prepended, like every other s3dol key). The object key is server-generated (PresignedUpload.key). Returns None for an anonymous store (no signing capability, as s3dol.urls() does).

When budget is given, the bucket’s versioning status is read first (one GetBucketVersioning call): with versioning enabled a re-posted form stores a new version each time, so on_versioned_bucket decides: 'warn' (default) emits VersionedBucketWarning, 'raise' refuses with ConfigurationError, 'ignore' skips the call.

Raises ConfigurationError for a bad prefix, size range, expires_in or on_versioned_bucket, and UploadBudgetExceeded if budget refuses.

Return type:

Optional[PresignedUpload]
